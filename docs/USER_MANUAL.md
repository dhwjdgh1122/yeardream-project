# YearDream 사용자 설명서

## 분석 이력·검토 관리 (최신 소스·release-20261025-04 이후)

기존 release-20261025-03 배포본에는 이 기능이 없습니다. 최신 소스로 실행하거나 새로 빌드한 뒤 탐지 화면의 **분석 이력·후보 검토 관리**를 누릅니다. 저장된 URL을 선택하면 원문·위치·수집 경고와 검토 기록을 볼 수 있습니다. 검토 결과를 선택하고 검토자·판단 이유를 입력해 기록을 추가합니다. 이전 검토와 원래 제출 결과는 유지됩니다. 이 기록은 법적 판단이나 제출 승인이 아닙니다.

이력은 이 PC의 `%LOCALAPPDATA%\YearDream\history.sqlite3`에 보관합니다. 앱 종료 후 복사해 백업할 수 있으며 실행 파일이나 기존 result.json을 바꿔도 DB는 별도로 남습니다. DB 저장 실패 안내가 나오면 현재 결과는 다운로드할 수 있지만 해당 분석 이력은 저장되지 않습니다. 분석 전체 실패는 이력에 저장하지 않습니다. 외부 AI API·로컬 AI 모델·RAG는 아직 사용하지 않습니다.

**결과 생성 위치: `YearDream.exe`가 있는 폴더의 `result.json`과 `result_extra.json`.** 다운로드 버튼은 브라우저 다운로드 폴더에 별도 사본을 저장합니다. 결과 파일은 성공한 다음 분석에서 갱신되므로 보존할 결과는 다른 폴더에 복사하세요. 여러 분석의 동시 실행은 피하세요.

## 실행

1. Windows 11 x64 PC에서 배포 ZIP을 쓰기 가능한 폴더에 **전체 압축 해제**합니다. ZIP 안에서 바로 실행하거나 exe만 따로 옮기지 않습니다. `_internal` 폴더도 필요합니다.
2. `YearDream.exe`를 실행합니다. Python을 설치할 필요가 없습니다. 서버 콘솔과 기본 브라우저 화면이 열립니다. 화면이 열리지 않으면 콘솔에 표시된 `http://127.0.0.1:8000` 주소에 접속합니다.
3. 분석할 HTTP(S) URL을 입력하고 기본 분석 또는 동적 페이지 분석을 선택한 뒤 ‘탐지 실행’을 누릅니다. 동적 분석은 설치된 Microsoft Edge가 필요합니다. 기본 분석에는 Edge가 필요하지 않습니다.
4. 결과와 경고, 특징·제출 후보·검토 대상 건수를 확인합니다. 필터는 화면만 바꾸며 다운로드 파일은 해당 분석의 전체 결과를 포함합니다.
5. 종료할 때 콘솔 창에서 `Ctrl+C`를 누릅니다. 브라우저 탭만 닫으면 서버는 계속 실행됩니다.

PowerShell에서 실행할 수도 있습니다.

```powershell
.\YearDream.exe
.\YearDream.exe --port 8010
.\YearDream.exe --no-browser --port 8010
```

기본 포트는 8000이고 서버는 이 PC의 127.0.0.1에서만 엽니다. `--port 0`은 사용 가능한 포트를 자동 선택하고 실제 주소를 콘솔에 표시합니다. 네트워크 접근이 가능한 환경에서 대상 웹페이지를 수집하며 GPU·외부 AI API·계정·API 키는 사용하지 않습니다. Edge와 대상 사이트의 외부 리소스에는 네트워크 접근이 발생할 수 있습니다.

## 진행 표시·설정·중단 (release-20261025-06)

문서 한도·링크 깊이·시간 예산(분)을 정한 뒤 탐지를 실행합니다. 시험 기본값은 **100문서·깊이 4·25분**이고, 문서 1~1000개·깊이 0~20·시간 1~30분을 설정할 수 있습니다. 문서 수는 실패/iframe을 포함하며 실제 HTML 탐지 완료 수와 다를 수 있습니다. 이 수치들은 공모전 지정 한도가 아니며 100문서 처리나 사이트 전수 탐지를 보장하지 않습니다. 짧은 작업은 예산을 다 쓰지 않고 종료합니다.

100개·4단계·25분은 미리 정한 **변경 가능한 기본값**이며 고정 최대치가 아닙니다. 사용자는 실행 전에 입력란에서 바꿀 수 있습니다. 예를 들어 문서 300개·깊이 11도 허용됩니다. 먼저 시간 한도에 도달하거나 방문할 링크가 소진되면 설정한 개수보다 적게 처리할 수 있습니다.

| 설정 | 기본값 / 입력 범위 | 용도와 예시 |
|---|---|---|
| 문서 한도 | 100 / 1~1,000개 | 수집을 시도할 문서 컨텍스트 수의 상한입니다. 게시판 목록·게시글·iframe과 실패한 시도도 포함하므로, 100으로 설정해도 게시글 100개를 분석한다는 뜻은 아닙니다. |
| 링크 깊이 | 4 / 0~20단계 | 시작 URL을 0단계로 보고 링크 이동마다 1단계 증가합니다. 예: 메인(0) → 참여마당(1) → 게시판 목록(2) → 게시글(3). iframe 진입 깊이는 별도로 제한하며 링크 깊이는 그대로 유지합니다. |
| 시간 예산(분) | 25 / 1~30분 | 수집·탐지에 사용할 시간의 상한입니다. 25분을 설정해도 반드시 25분을 기다리는 것은 아니며, 한도 확인 뒤 완료한 문서의 결과를 반환합니다. |

문서 한도나 시간 예산에 먼저 도달하면 탐색을 중단합니다. 링크 깊이를 넘는 링크는 제외하며, 그 안에서 방문할 다른 링크가 없으면 종료합니다. 한도를 높이면 탐색 범위와 소요 시간이 늘어날 수 있지만 사이트 전체 검사를 보장하지 않습니다. 우선 기본값으로 실행하고 결과의 실제 방문·미방문 범위와 종료 이유를 확인해 조정합니다.

진행 중에는 움직이는 가로 막대와 수집/탐지 완료·대기·실패 문서 수, 현재 URL, 경과 시간을 표시합니다. 탐색할수록 링크가 새로 발견되므로 퍼센트 검사율이나 정확한 남은 시간은 표시하지 않습니다. 한도 100 중 40문서를 처리했다는 것은 사이트 전체의 40%를 검사했다는 뜻이 아닙니다.

분석 안내는 첨부 제외·iframe 제외·수집 실패·한도 도달 등 같은 사유끼리 묶어 건수로 표시합니다. 중단·실패를 먼저 보여주며 개별 URL과 원문은 항목을 펼쳐 확인합니다. 펼친 목록은 스크롤할 수 있고 동일 원문은 중복 건수를 표시합니다. 화면 요약과 관계없이 상세 JSON·광고 후보 다운로드에는 전체 원문 안내가 유지됩니다.

**중단하고 현재 결과 보기**를 누르면 완료한 문서의 결과를 저장/표시합니다. 완료한 문서가 없으면 새 결과를 만들지 않고 이전 결과 파일을 유지하며 다운로드는 비활성화합니다. 이미 진행 중인 통신·DOM 파싱을 즉시 강제 종료하지 않으므로 중단 정리와 시간 예산을 일부 초과할 수 있습니다. 25분 기본값은 공식 30분 상한에 여유를 두려는 시험 설정이며 엄격한 상한 준수 인증은 아닙니다.

새로고침한 뒤 진행 확인 재시도를 누르면 같은 탭에 보관한 작업 ID로 진행을 다시 조회합니다. 앱 자체를 종료/재시작하면 진행 중 작업은 복원되지 않으며 완료된 DB 이력만 남습니다. 한 번에 분석 하나만 실행할 수 있습니다. 네트워크 조회 실패 시 재시도로 상태를 확인하며 작업을 중복 생성하지 않습니다.

게시판 목록·게시글을 일반 안내 링크보다 우선하고 내용 후보가 발견된 문서의 후속 링크도 우선합니다. 페이지 넘김은 HTML 링크로 노출된 경우에 한해 깊이/문서/시간 한도 안에서 따릅니다. URL이 xboard/board.php의 동일 게시글이면 목록 문맥용 쿼리 차이를 중복으로 줄입니다. 첨부파일 링크·HTML 아닌 응답은 제외하며 정적 HTTP HTML은 5 MiB로 제한합니다. 자동 클릭·스크롤·로그인이나 첨부파일/OCR 분석은 지원하지 않습니다. 제외/미방문과 실패는 범위 상세에서 확인합니다.

작성·수정·삭제·답글 작성·로그아웃 등 작업 링크는 자동 수집에서 제외합니다. xboard의 바로 이동 링크는 공개 본문 보기 경로로 읽으며 원래 발견 링크와 요청 URL을 함께 표시합니다. 일부 게시판의 별도 동작 방식은 추가 검증이 필요하고 글 번호가 보이는 링크에 도달했다는 것만으로 본문 분석 성공을 판단하지 않습니다.

## 결과 해석과 범위

‘실제 탐색·분석 범위’는 입력한 URL에서 설정한 한도 내에 탐색·분석한 결과를 안내합니다. 미방문하거나 접근하지 못한 페이지에는 탐지되지 않은 광고가 남아 있을 수 있습니다. 이는 불법광고 탐지 목적을 제한하는 표현이 아니라 이번 실행에서 확인한 범위를 설명하는 안내입니다. 탐색 방식과 결과 유형 필터의 설명은 별도 보조 문구로 제공합니다.

현재 내용 규칙은 도박/성인물 주제와 같은 문맥에 있는 검색 유도도 확인합니다. ‘구글검색’ 같은 문구가 홍보 제목/본문과 연결되면 후보가 나올 수 있습니다. 검색 금지·예방교육·차단 안내는 구분하지만 후보는 여전히 검토 대상입니다. 페이지 아래 게시물 목록도 분석하므로 입력한 글 외의 목록 제목이 함께 나타날 수 있습니다.

결과는 문구·유형·제출 후보/검토 필요 상태·판단 이유·페이지·위치를 담은 카드로 표시합니다. 홍보 내용 후보는 별도 목록입니다. 수집 경고는 목록 위에 표시하며 전체 집계와 현재 필터의 표시 건수를 구분합니다. 상세 JSON은 접힌 ‘상세 JSON 보기’를 열어 확인합니다. 오류가 나면 이전 카드를 비우고 오류 이유를 표시합니다.

완전한 연속 자모 구간이 ㅋ/ㅎ 두 글자 이상으로만 구성된 웃음 표현은 JAMO 특징에서 제외합니다. 단독 ㅋ/ㅎ·다른 자모·모음이 붙은 자모 분리 표현은 유지합니다. 웃음 표현이 있어도 투명/숨김 CSS는 별도 탐지합니다. 이 예외는 문장 전체를 정상이라고 판정하는 규칙이 아닙니다. 이전의 고정 confidence 수치는 검증된 확률이 아니므로 API/화면에서 제거했습니다.

- `result.json`: HOMOGLYPH·JAMO·TRANSPARENT·OFFSCREEN 특징 중 관련 홍보 원문 구간과 연결된 제출 후보입니다. 규칙이 선택한 항목은 is_violation=true이며 법적 확정 판단을 뜻하지 않습니다.
- `result_extra.json`: 필수 4종과 별도인 도박·성인물 홍보 내용 후보입니다. 일반 표시 광고를 임의의 필수 기법으로 분류하지 않습니다.
- 광고 후보 다운로드: 검수용 위치·문맥·규칙 정보입니다. 후보는 사람이 확인해야 합니다. 특징만 있는 항목은 화면에 검토 대상으로 보존합니다.
- 0건 결과도 빈 findings 배열을 가진 파일로 저장합니다. **0건은 광고 부재를 입증하지 않습니다.** 부분 결과는 수집/시간 제한 경고를 함께 확인합니다.
- 완전한 수집 실패나 분석 완료 전 시간 초과에서는 기존 결과 파일이 남을 수 있습니다. 화면의 성공 여부와 파일의 meta 시각을 확인하여 이전 결과를 새 결과로 오인하지 마세요.

화면 기본값은 문서 최대 100개, 링크 깊이 4, iframe 깊이 3, 공유 시간 예산 25분입니다. 동적 모드는 초기 DOM 로드 뒤 기본 500ms 대기합니다. 자동 스크롤·클릭·로그인·이미지/OCR·Shadow DOM·외부 도메인 프레임 분석은 지원하지 않습니다. 어휘 밖 광고와 문맥·스타일 변형에 오탐·미탐이 남습니다. 전체 사이트 정확도와 공식 평가 환경의 엄격한 시간 상한은 검증 완료가 아닙니다. 이전 버전의 다른 PC 사용자 확인을 새 버전 전체 검증으로 소급하지 않습니다.

## 사용자 직접 사용 점검

최신 소스와 release-20261025-05 이후의 탐지 화면에는 **실제 탐색·분석 범위**가 표시됩니다. 수집 시도/성공·탐지 완료·실패 문서 수와 발견한 미방문 URL 수를 구분하고, 상세 목록에서 URL·iframe 위치·미방문/제외 이유를 확인할 수 있습니다. 수집 성공이 탐지 완료를 뜻하지 않으며, 같은 URL의 iframe도 위치별 문서로 셉니다. 미방문 목록은 이미 발견한 URL만이며 첨부파일/바로 이동 링크의 대상 제외도 사유별로 표시합니다. 사이트 전체 누락 수가 아닙니다. 종료 문구도 수집 범위의 분석 종료를 뜻하며 사이트 전체 검사 완료를 뜻하지 않습니다.

문서 8개·깊이 2·60초는 이전 UI의 구현 설정이었으며 release-06 화면은 위의 100문서·깊이4·25분으로 조정할 수 있습니다. ‘전체 유형’은 결과 필터이며 탐색 범위를 사이트 전체로 바꾸는 설정이 아닙니다. 범위 기록이 없는 이전 DB 이력은 새 정보가 있는 것으로 소급하지 않습니다. 기존 submission-20261025-02에는 진행 표시/중단과 새 탐색 정책이 없습니다.

아래 항목은 실제 수행한 범위만 체크하고 날짜·Windows/Edge 버전·대상 URL·불편/오류를 기록합니다. 이 표는 개발 PC의 자동 검사 결과와 구분합니다. 2026-10-25 사용자 진술로 현재 PC의 종료·재실행 후 분석 이력과 후보의 검토 결과·검토자·판단 이유 유지를 확인했습니다. 이어 다른 PC의 정상 실행과 종료·재실행 후 기록 유지도 사용자 확인을 받았습니다. 정확한 실행 파일/Windows/Edge 버전, 다른 PC의 분석 모드·다운로드·검토 필드별 상세 결과는 미기록이며 전체 점검표 통과로 확대하지 않습니다. 다른 PC 기록은 OTHER_PC_CHECKLIST.md를 따릅니다.

## 문제 해결 안내

| 증상 | 확인 방법 |
|---|---|
| 실행 직후 종료 | PowerShell에서 exe를 실행해 오류를 확인합니다. 전체 폴더 압축 해제 여부를 확인합니다. |
| Cannot start / 포트 충돌 | 실행 중인 프로그램을 종료하거나 `--port 8010`으로 실행합니다. |
| 쓰기 권한 오류 | Program Files 등 제한된 폴더 대신 사용자가 쓸 수 있는 폴더로 전체 배포 폴더를 옮깁니다. |
| 동적 분석 503 | Microsoft Edge 설치/실행 환경을 확인합니다. 필요하면 기본 분석을 사용합니다. |
| 수집 실패·시간 초과 | 입력 URL·인터넷 연결·사이트 접근 제한과 경고를 확인합니다. |
| 실행 파일 경고/차단 | 이 빌드는 코드 서명되지 않았습니다. 조직 정책에 따라 배포 담당자에게 파일 출처와 검사 결과를 확인합니다. |

이 패키지는 분석 UI/API 실행용입니다. 저장본 수동 검토·평가 CLI는 소스와 Python 환경에서 README 절차로 실행합니다. 이 설명서는 공모전 제출 서류를 대체하지 않습니다.
