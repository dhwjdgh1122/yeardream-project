## 2026-10-25 2차: 목록 후보 40개 검수와 반복 진단

1차에서 남겼던 목록 후보 40개를 추가 검수했습니다. 각 목록 위치의 원문·연결 주소를 확인하고 연결된 게시물의 제목/본문도 확인했습니다. 총 연결 대상은 게시물 번호 141·144·145·147·148·149·150·151의 8개입니다. 이 중 144·145·147·149는 새로 저장해 문맥 근거로 보존했고 기존 4개는 1차 저장본을 사용했습니다. 외부 광고 서비스에 접속하지 않고 교육청에 게시된 내용만 확인했습니다. Codex의 내용 존재 검수이며 법적 위반 확정이나 사용자의 직접 판단을 뜻하지 않습니다.

목록의 특정 서비스 검색 유도와 연결 글의 시청/가입/베팅 서비스 홍보 문맥을 근거로 40개를 내용 양성으로 표시했습니다. 검수 항목은 기존 제목/본문 28개에 목록의 해당 범주 40개를 더한 **68개**입니다. 목록의 반대 범주와 미검출 영역을 전수 검수하지 않았습니다.

| 같은 v5 규칙, 검수 범위 변경 | TP | FP | FN | TN | 미검수 예측 |
|---|---:|---:|---:|---:|---:|
| 1차: 제목/본문 28항목 | 10 | 0 | 0 | 18 | 40 |
| 2차: 목록 포함 68항목 | 50 | 0 | 0 | 18 | 0 |

**검출되지 않은 영역의 누락 여부는 아직 전수 검수하지 않았으므로 complete=false, 전체 precision/recall/F1은 null을 유지합니다.** ‘미검수 예측 0’은 현재 예측 목록을 모두 확인했다는 뜻이며 전체 페이지의 광고를 빠짐없이 찾았다는 뜻은 아닙니다. 탐지 규칙과 현재 예측은 같고 검수 라벨만 확장했습니다. 4개 추가 연결 문맥은 근거로 보존하며 평가 케이스 수 7개에는 더하지 않았습니다.

반복은 범주와 정확한 원문 바이트를 기준으로 진단합니다. 검수 68항목 전체가 아니라 **현재 예측 50개**에 대한 진단이며, 공백·Unicode·범주가 다르면 다른 그룹입니다.

| 반복 진단 | 건수 |
|---|---:|
| 예측 위치/범주 | 50 |
| 고유한 범주+정확한 원문 그룹 | 16 |
| 두 번 이상 나타난 원문 그룹 | 6 |
| 그 반복 그룹에 속한 전체 예측 | 40 |
| 각 그룹 첫 건을 제외한 추가 반복 | 34 |
| 목록에서 연결된 서로 다른 게시물 | 8 |

성인물 검색 유도 문구 3종은 15·5·5회, 도박 관련 검색 유도 문구 3종은 5·5·5회 나타났습니다. 같은 잘린 제목 하나가 게시물 3개를 가리키므로 정확한 원문 그룹 수와 연결 대상 수가 다릅니다. 같은 제목이라도 위치별 평가/제출 단위는 유지하며, 이 진단이 의미상 서로 다른 광고 수나 독립 표본 수를 산출하는 것은 아닙니다. 단일 도메인에 반복된 목록이므로 표본 다양성과 일반 정확도로 확대 해석하지 않습니다.

2차 자료는 `.validation/real-content-review-20261025-02`에 별도로 만들었습니다. manifest와 capture/정답 해시, 목록별 원문 해시·연결 주소·연결 문맥 capture 해시를 담은 list-review-evidence.json, supporting-context의 새 문맥 4개, report-v5-list-reviewed.json을 보존합니다. 1차 자료/보고서는 유지합니다. HTML·정답·상세 보고서는 Git에서 제외합니다.

```powershell
.venv\Scripts\python.exe -B scripts/evaluate_suite.py .validation/real-content-review-20261025-02/manifest.json --output .validation/real-content-review-20261025-02/report-next.json
```

`prediction_repetition`은 content 평가에서만 제공하며 feature 평가에서는 null입니다. 범주+원문 SHA-256별 반복 건수·케이스 수·URL/위치를 기록합니다. 원문이 없으면 임의로 빈 문구를 묶지 않고 오류로 처리합니다. 점수의 위치 단위나 지표 계산을 변경하지 않습니다.

다음 검증은 현재 미검출 영역과 독립된 다른 도메인/표현·필수 4종 은닉 사례를 포함한 검수입니다. 별도 Windows PC 검증과 제출 준비도 남아 있습니다.

원본 캡처/이전 검토를 수정하지 않고 `.validation/real-content-review-20261025-01/cases`에 사본과 새 정답을 만들었습니다. manifest.json은 capture/정답 SHA-256에 연결하며 report-v4.json과 report-v5.json을 각각 보존합니다. 실제 HTML·정답·상세 보고서는 Git에서 제외합니다. 새 수집 4개와 이전 수집 3개를 사용했으며 수집의 링크/프레임 제외 경고도 보고서에 포함합니다.

## 재현 명령

현재 PC의 저장 자료가 있으면 소스 환경에서 실행합니다. 실행 파일에는 이 평가 CLI를 포함하지 않습니다.

```powershell
.venv\Scripts\python.exe -B scripts/evaluate_suite.py .validation/real-content-review-20261025-01/manifest.json --output .validation/real-content-review-20261025-01/report-next.json
```

출력은 반드시 새 경로여야 합니다. 과거 보고서 파일을 갱신하지 않습니다. 코드 수정 후 같은 입력으로 새 보고서를 만들어 비교합니다. v4 보고서는 당시 코드를 실행해 보존한 기준선이며 현재 명령을 실행하면 현재 코드의 결과가 나옵니다. manifest 자체/평가 코드와 케이스별 탐지 코드 해시도 기록합니다.

다른 데이터셋을 만들 때는 README의 capture/정답 검수 절차로 저장본을 준비하고, suite JSON을 작성합니다. 각 directory는 manifest가 있는 폴더 안의 상대 경로여야 합니다. kind는 content 또는 feature, dataset_type은 real_saved_pages 또는 synthetic입니다. dataset_type은 작성자의 분류이지 실제 데이터나 독립성 인증이 아닙니다. scope에 수집/검수 범위·제약을 적고 cases에 id/directory/capture_sha256/labels_sha256을 지정합니다. labels 해시는 content이면 content-labels.json, feature이면 labels.json 파일의 실제 바이트 SHA-256입니다.

중복 ID/폴더·같은 페이지의 반복 수집/동등 URL·다른 케이스와 겹치는 페이지는 거부해 건수를 부풀리지 않습니다. 서로 다른 게시물 화면에 반복되는 목록은 별도 요소로 남으므로 데이터 다양성이 높아진 것으로 해석하지 않습니다. 입력 해시·HTML 해시·경로·선택자 검증도 적용합니다. 모든 저장 페이지의 해당 정답을 완전히 검수한 경우에만 complete=true를 쓰고, 일부 케이스라도 부분 검수면 집계 지표는 null로 유지합니다.

다음 검증은 미검수 목록 후보와 독립적인 다른 도메인/표현·4종 은닉 사례를 늘리고 별도 Windows PC에서 실행하는 것입니다. 이 기록으로 실제 사이트 전체 정확도나 공모전 통과를 주장하지 않습니다.
