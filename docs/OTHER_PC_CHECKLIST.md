# 다른 Windows PC 실행 점검표

**결과 위치: 압축 해제한 `01_run/YearDream` 폴더의 `result.json`, `result_extra.json`.**

2026-10-25 사용자가 다른 PC에서도 정상 테스트를 완료했고 종료·재실행 후 기록이 유지된다고 보고했습니다. 다른 PC의 정상 실행·재실행 및 기록 유지는 사용자 확인으로 기록합니다. 아래 환경 정보와 개별 분석/다운로드 항목의 상세 결과는 아직 전달받지 않았습니다. 빌드 PC의 자동 검사와 구분하며 실제 확인한 범위만 기입합니다.

최신 DB 포함 배포본(release-20261025-04 이후)을 기준으로 합니다. 같은 개발 PC에서 수행했다면 다른 PC 검증 통과로 기록하지 않습니다. 먼저 현재 PC의 사용자 점검을 하려면 USER_MANUAL.md의 사용자 직접 사용 점검을 따릅니다.

아래 사용자 확인은 release-20261025-05 범위 표시 보완 전 보고입니다. 새 release-05의 실행/범위 화면을 다른 PC에서 검사한 것으로 소급하지 않습니다. 새 버전 점검 시 수집/탐지 문서·알려진 미방문 URL·제외 iframe 표시와 긴 URL의 화면 줄바꿈도 확인합니다.

1. ZIP 체크섬을 대조하고 쓰기 가능한 한글/공백 경로에 **전체 압축 해제**합니다. exe만 복사하지 않습니다.
2. `01_run/YearDream/YearDream.exe`를 실행합니다. 콘솔과 브라우저 화면/주소를 확인합니다. 열리지 않으면 콘솔 주소로 직접 접속합니다.
3. 기본 분석으로 접근 가능한 HTTP(S) 페이지를 실행하고 완료/경고·결과 파일 두 개·메타 시각을 확인합니다. 대상 URL과 결과를 기록합니다. 사이트 변경/접근 제한이 있으면 실패 원인을 기록합니다.
4. Edge가 설치된 상태에서 동적 분석을 실행하고 화면·경고·결과 파일을 확인합니다. 독립 광고 정답이 없는 경우 건수를 기대값으로 단정하지 않습니다.
5. 필터 후 다운로드가 전체 해당 결과를 저장하는지 확인합니다. 0건도 빈 findings 배열로 생성되는지 확인합니다. 수집 실패 시 이전 결과와 새 결과를 혼동하지 않도록 화면/시각도 확인합니다.
6. 터미널 작업 폴더와 무관하게 결과가 exe 옆에 생성되는지 확인합니다. 결과/로그/화면을 기록용 별도 폴더에 보관합니다.
7. 콘솔에서 Ctrl+C로 종료합니다. 다시 시작할 수 있는지 확인합니다. 포트가 사용 중이면 `YearDream.exe --port 8010`으로 확인합니다.
8. 분석 이력 화면에서 새 분석을 조회합니다. 후보가 있으면 검토자·이유와 함께 판단 보류 등의 검토를 추가하고 새로고침 후 확인합니다. 후보가 없다면 검토 입력은 미실시로 기록하며 정상으로 단정하지 않습니다.
9. 프로그램 종료·재실행 후 이력과 검토가 남는지 확인합니다. DB 위치 `%LOCALAPPDATA%\YearDream\history.sqlite3`와 exe 옆 결과 파일의 구분을 확인합니다. 기존 사용자 DB는 지우지 않습니다. 검토가 기존 제출 JSON을 변경하지 않는지도 확인합니다.
